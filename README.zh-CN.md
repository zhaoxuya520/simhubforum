# 切卡闪退：读回入口的协程参数类型修复

用户反馈上次普通开关接入跨芯片事务后，切卡会闪退。本环境 ADB 设备列表为空，没有收到手机 FATAL EXCEPTION 日志，不能将代码分析结果当作用户手机崩溃堆栈。

已确认的缺陷：InternalSimCheckedRead.i(Object) 原先只将回调参数转换为 Lct0（协程接口），却直接把该寄存器传给 hh1.C(Ldt0;Lkt1;[B)。Ldt0 是具体协程基类，Lct0 接口不能在字节码类型检查中替代该基类。Android 验证器可能因此拒绝该类，VerifyError 也不会被原有只捕获 Exception 的业务错误分支处理。普通开关上次开始访问这条路径，暴露了已有的类型错误。

生产代码只修正这处转换：check-cast p1, Lct0 → check-cast p1, Ldt0。原生 hh1.s 的调度最终由 sb0 / rb0 等原生协程回调，实际参数所属的协程类型继承 Ldt0，与接收方法契约一致。没有删除跨芯片禁用、EID 核验、读回确认，没有修改签名证书、权限、界面或运营商身份。

新增独立于 Python 流程模拟的 DEX 检查：dexlib2 对真正 APK 内的代码做控制流寄存器类型分析，再根据 APK 的真实类继承关系检查新增适配器调用参数。固定上次发布 APK（SHA-256 bcf1a20e936548f56965eb33e000e9a35f8303e9d60a963b190b339cc6b46cc0）作为负例，准确报告 CheckedRead.i 的 Lct0 → Ldt0 参数不兼容；修正版检查 11 个适配器类、29 个方法、77 个调用、158 个引用参数，错误数为 0。构建会强制执行该检查；检查依赖版本和 SHA-256 固定在 validation/dex/toolchain.json。

验证还覆盖同步/挂起切卡、显式拒绝后的无刷新回退、取消/断连不重试、错误 EID 停止读回、旧配置未禁用时停止后续启用，以及两个原有开关入口保持接入事务、旧 USIM 提示保持移除。

这不是手机实测或 ART 执行。修复解决已确认的字节码类型缺陷，尚不能宣称用户设备的闪退及实际旧配置关闭已经得到实机确认。若仍退出，下一步必须依据本次崩溃堆栈定位其他原因。
