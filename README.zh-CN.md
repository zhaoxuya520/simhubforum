# 普通开关漏接跨芯片处理及错误 USIM 提示

用户已确认：新配置已经切换成功，问题是旧芯片配置仍启用且无法关闭。此前 USIM 身份诊断偏离了这一问题。

本次找到具体代码遗漏：cg0（详情回调）已使用 InternalSimMultiChipSwitch，但 px3 调用的 sj（普通开关回调）仍直接创建 hz3，只操作目标配置，不先禁用其他芯片配置。此前跨芯片事务测试没有覆盖这个 UI 入口，不能据此认为普通开关也已修复。

现在 sj 和 cg0 都调用相同跨芯片事务：逐芯片读取实际状态，在旧配置所属芯片发送禁用并读回确认，然后继续目标操作。沿用原有开关，不新增按钮，不通过启用同芯片另一配置来间接关闭旧配置。上一版的明确拒绝后无刷新回退仍保留。

删除 fd2 中 vowifi_sms_profile_mismatch 的整个提示卡片渲染分支，包括图标和容器；清空简体、繁体对应的“卡上的 USIM 还是之前的 Profile…”文案。没有关闭实际认证身份一致性检查。

新增 check_toggle_routes.py 检查所有原有 smali 文件，防止 sj / cg0 或其他 UI 入口继续直接创建 hz3 绕过跨芯片事务，并核验错误提示不显示。自动检查只能验证代码连接及模拟事务；旧芯片配置能否在用户设备真正关闭仍需实测，不能宣称已由模拟测试证明。
