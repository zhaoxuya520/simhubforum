# 跨芯片切换修正与 EID 核验版 check2

上一版未解决用户的一加实机跨芯片切卡。两张截图分别显示 ICCID 尾号 1056 和 2543 仍各自启用。本版不是实机已修复的结论。

已确认并修改的代码缺口：

- 旧协调入口只对 Ls4 传输类型执行；现在按实际发现的芯片数决定，所有已识别多芯片读卡器均进入协调流程，单芯片保留原流程。
- 原 D 芯片选择入口没有事务保护，可在协程等待时改写当前 AID。现在协调期间阻止外部切换芯片，内部选择有独立许可；结束、失败和取消释放保护；连接对象更换会停止事务。
- 旧逐芯片读取未确认所开通道实际 EID。现在每次扫描在同一管理通道先执行原 GET EID，再读取原 Profile 列表；EID 不符立即停止，不把别的芯片列表标到当前芯片上。沿用原安全门及管理通道清理。
- 增加原读卡器日志中的 [跨芯片] 记录，包含实际传输类、发现芯片数、目标 EID/ICCID 尾号、禁用命令和读回启用状态，均不记录完整身份或密钥。

切卡仍必须由配置启用操作发起；仅浏览芯片选择页不会自动禁用卡片。本版不伪造 Profile 禁用状态。若已存在两边同时启用，重新执行目标配置的启用操作才能触发协调。

370 项 JVM 断言（含 47 项跨芯片事务），22 项流程模拟（原 10、新协调 8、同通道 EID 读取 4）通过；51 个新旧方法引用核验通过。生产重建、长期证书 v2/v3 签名、自检白名单、16 KB 对齐和签名前后内容一致验证通过。未执行一加实机、真实 eSTK 调度或运营商验证。

请安装后执行一次明确的目标配置启用，再切回另一芯片配置。如果仍显示双启用或提示错误，请提供这次完整的 [跨芯片] 操作日志；它能判断实际入口是否运行、是否打开错误 EID、禁用请求是否成功以及显示是否陈旧。
